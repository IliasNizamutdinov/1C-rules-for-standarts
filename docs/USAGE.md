# Как применять правила

Правила не гарантируют соответствие всем стандартам фирмы «1С». Они заставляют агента разделять проверенные требования, методические рекомендации и собственные советы.

## Какие файлы участвуют

Для кода модуля: `10-modules`. Для конструкций языка: `11-language`. Для запроса: еще `20-queries`. Для проведения и записи: `30-data-architecture`. Для формы, клиента и прав: `40-client-server-security` и `50-forms-applied`. Политика `00-policy` нужна всегда.

В Cursor файлы `10-modules.mdc` и `11-language.mdc` прикрепляются к открытому `.bsl` или `.os`. Остальные тематические файлы Agent берет по описанию. Если тема в запросе не названа, попросите прочитать конкретный `.mdc`: упоминание пути не вставляет текст само.

В OpenCode семь файлов из `opencode.json` загружаются вместе, если конфигурация прочитана. Проверка описана в [INSTALL_OPENCODE.md](INSTALL_OPENCODE.md).

## Что агент проверяет

1. Есть ли у замечания идентификатор из `catalog/adapter-manifest.json`.
2. Какой у правила тип и сила.
3. Для официального правила — совпадает ли ссылка с каталогом.
4. Не меняется ли учетный результат, если просили только оформление.
5. Нет ли объектов, которых пользователь не показывал.

## Форма отчета

```text
Официальные требования
- STD-DATA-008, модуль объекта, процедура ПередЗаписью.
  Нет выхода при ОбменДанными.Загрузка.
  Источник: https://its.1c.ru/db/v8std/content/773/hdoc

Официальные методические рекомендации
- STD-MOD-002, в конце модуля оставлен закомментированный вызов.
  Это рекомендация #std456, не отдельный обязательный пункт до этой пометки.

Инженерные рекомендации
- ENG-REV-005, СуммаНДС() вызывается в цикле и внутри выполняет запрос.
  Это не формулировка стандарта. Рядом применим STD-QRY-003, если запросы однотипные.

Требования проекта
- Нет включенных правил.

Нужна проверка по источнику
- Предложение вынести код в ОбщегоНазначения не подтверждено: наличие БСП в конфигурации не показано.
```

Фразу «нарушен стандарт 1С» оставляют только первой группе и только вместе с идентификатором. Для второй группы пишут «методическая рекомендация». Для третьей — «инженерная рекомендация».

## Что не стоит просить

Не просите перенести в код длинные примеры с ИТС. Не просите объявить прием сообщества обязательным стандартом, если его нет в `rules/official`. Не включайте `90-project-template`, пока в нем примеры `PRJ-TPL-*`: они выключены и описывают вымышленный префикс.
