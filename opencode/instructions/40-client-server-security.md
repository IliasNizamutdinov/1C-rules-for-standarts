# Клиент, сервер и безопасность

Официальные правила клиент-серверного взаимодействия, прав и безопасного кода. ENG-REV-007 описывает асинхронный вызов и не цитирует отдельную статью про оператор Ждать.

### STD-CS-001. Серверные вызовы с клиента сокращают и не тащат лишние данные

- Тип: `OFFICIAL_STANDARD`
- Сила: требование источника
- Проверка источника: 2026-10-15, статус `body_reviewed`
- Область платформы: управляемое приложение, мобильное приложение, обычное приложение
- Область: формы, клиент-сервер

[Минимизация количества серверных вызовов и трафика](https://its.1c.ru/db/v8std/content/487/hdoc) (#std487, пункты 1.1, 4.2, 4.3, 5.1, 9, 11, 12)

Число серверных вызовов из клиентского кода контролируют. При открытии формы сервер не вызывают из ПриОткрытии и ПриПовторномОткрытии: данные готовят в ПриСозданииНаСервере. Локальная команда формы приводит не больше чем к одному серверному вызову. Серверную логику записи размещают в ПередЗаписьюНаСервере, ПриЗаписиНаСервере и ПослеЗаписиНаСервере. На сервер передают только нужные данные. Параметры серверного метода, который вызывают с клиента, помечают Знач, если значение не нужно возвращать. Несколько обработчиков ожидания, которые опрашивают сервер, не подключают.

Что делает агент:
- Не вызывать сервер в цикле клиентского обработчика.
- Переносить чтение при открытии в ПриСозданииНаСервере.
- Ставить Знач у параметров серверной процедуры, вызываемой с клиента, если обратная передача не нужна.

### STD-CS-002. Тяжелый алгоритм выполняют на сервере

- Тип: `OFFICIAL_STANDARD`
- Сила: требование источника
- Проверка источника: 2026-10-15, статус `body_reviewed`
- Область платформы: управляемое приложение, мобильное приложение, обычное приложение
- Область: формы, клиент-сервер

[Минимизация кода, выполняемого на клиенте](https://its.1c.ru/db/v8std/content/629/hdoc) (#std629, пункты 1.1, 1.2, 2.1, 2.2)

На клиенте не выполняют тяжелые расчеты: в веб-клиенте интерпретатор медленнее. Такие алгоритмы размещают на сервере и вызывают их минимальное число раз. На клиенте оставляют быстрые действия, например пересчет доступности элементов, если один контекстный вызов сделает форму хуже. Код оборудования и клиентских программ может оставаться на клиенте; для веб-клиента его закрывают инструкцией препроцессора.

Что делает агент:
- Не перебирать большие коллекции и не строить пакеты данных на клиенте.
- Оставлять на клиенте только реакцию интерфейса.

В клиентском коде ссылку на предопределенный элемент, значение перечисления или точку маршрута получают функцией ПредопределенноеЗначение. Менеджеры справочников и перечислений там недоступны.

Что делает агент:

### STD-CS-004. Контекстный вызов сервера формы используют, только когда нужен контекст

- Проверка источника: 2026-10-15, статус `body_reviewed`
- Область платформы: управляемое приложение, мобильное приложение
- Область: формы

[Контекстная и внеконтекстная передача управления на сервер](https://its.1c.ru/db/v8std/content/636/hdoc) (#std636, пункты 1, 2.1, 3)

Внеконтекстный вызов &НаСервереБезКонтекста передает только указанные параметры. Контекстный &НаСервере дополнительно передает измененные данные формы. Объекты ДанныеФормыСтруктура, ДанныеФормыКоллекция, ДанныеФормыДерево и ТабличныйДокумент не передают на сервер параметром по значению.

Что делает агент:
- Если серверу достаточно нескольких значений, писать &НаСервереБезКонтекста.
- Не передавать табличный документ и данные формы коллекции параметром по значению.

### STD-CS-005. В веб-клиенте нет модальных окон и синхронных вызовов

- Тип: `OFFICIAL_STANDARD`
- Сила: обязательная формулировка источника
- Проверка источника: 2026-10-15, статус `body_reviewed`
- Область платформы: управляемое приложение, платформа 8.3 и выше, конфигурации для веб-клиента
- Область: формы

[Ограничение на использование модальных окон и синхронных вызовов](https://its.1c.ru/db/v8std/content/703/hdoc) (#std703, пункты 1, 2, 3)

Для конфигурации, которая работает в веб-клиенте на платформе 8.3 и выше, модальные формы и диалоги запрещены. Свойство «Режим использования модальности» устанавливают в «Не использовать». Вместо модальных методов вызывают немодальные аналоги с блокировкой окна владельца. В ПриЗавершенииРаботыСистемы асинхронные вызовы недопустимы.

Что делает агент:
- Не вызывать Вопрос, Предупреждение и ОткрытьФормуМодально в управляемой форме.
- Использовать немодальный аналог с описанием оповещения.
- Не описывать конкретную цепочку Ждать как цитату стандарта: стандарт требует немодальный вызов, а выбор асинхронного синтаксиса платформы — отдельное инженерное решение.

- Тип: `OFFICIAL_STANDARD`
- Сила: в статье есть и требование, и рекомендация; см. текст правила
- Проверка источника: 2026-10-15, статус `body_reviewed`
- Область платформы: управляемое приложение, мобильное приложение, обычное приложение
- Область: общие модули, производительность

[Использование модулей с повторным использованием возвращаемых значений](https://its.1c.ru/db/v8std/content/724/hdoc) (#std724, пункты 1, 2, 3, 5)

Модуль повторного использования применяют для дорогих и часто читаемых результатов. Нельзя кэшировать то, что считается быстрее чтения кэша, например строковую константу. Диапазон параметров кэшируемой функции должен быть узким. Возвращаемые данные не изменяют; предпочтительны фиксированные коллекции. На время сеанса нельзя возвращать менеджер временных таблиц, запрос и объекты базы.

Что делает агент:
- Не помещать в ПовтИсп функцию, которая возвращает константу или ДокументОбъект.
- Не изменять массив, полученный из кэша.

Серверный вызов, который в обычном сценарии длится больше ориентира в 8 секунд, выполняют фоновым заданием. К таким операциям относятся тяжелый отчет, групповая обработка, обмен и заполнение большой табличной части. Иначе браузер может прервать сценарий.

### STD-CS-009. Временный файл получают штатным именем и удаляют в том же серверном вызове

- Область платформы: управляемое приложение, мобильное приложение, обычное приложение

[Доступ к файловой системе из кода конфигурации (Раздел обновлен!)](https://its.1c.ru/db/v8std/content/542/hdoc) (#std542, пункты 1.1, 1.3, 1.4, 1.5)

Имя временного файла получают через ПолучитьИмяВременногоФайла. На веб-клиенте, где метода нет, используют КаталогВременныхФайлов и уникальный идентификатор. После работы файл удаляют сами. На сервере работу с временным файлом заканчивают в том же серверном вызове: следующий вызов может попасть на другой компьютер кластера.

- Удалять файл в блоке завершения того же вызова.
- Не рассчитывать, что файл дождется следующего серверного вызова.

### STD-SEC-001. Серверный программный интерфейс не отдает клиенту лишние данные

- Тип: `OFFICIAL_STANDARD`
- Сила: требование источника
- Проверка источника: 2026-10-15, статус `body_reviewed`
- Область платформы: управляемое приложение, мобильное приложение, обычное приложение
- Область: безопасность, общие модули, формы

[Безопасность прикладного программного интерфейса сервера](https://its.1c.ru/db/v8std/content/678/hdoc) (#std678, пункты 1, 1.1, 1.2, 1.3, 3)

Экспортные серверные методы с признаком «Вызов сервера» и серверные методы форм образуют открытый программный интерфейс: их можно вызвать извне так же, как вызывает клиент. В них не размещают бизнес-логику, которая не относится к форме. Клиенту не передают данные, которые пользователь не должен видеть. Особо проверяют методы с привилегированным режимом.

Что делает агент:
- Не делать экспортной серверную функцию, которая возвращает произвольные данные базы на клиент.
- Не размещать расчет проведения в серверной процедуре модуля формы.

[Ограничение на установку признака «Вызов сервера» у общих модулей](https://its.1c.ru/db/v8std/content/679/hdoc) (#std679, пункты 1)

Не всем серверным общим модулям ставят «Вызов сервера». В таком модуле оставляют только методы, которые клиент вправе вызвать и которые возвращают только разрешенные данные. Остальной серверный код лежит в модуле без этого флажка.

Что делает агент:
- Новую серверную процедуру без клиентского вызова помещать в модуль без «Вызов сервера».
- Не включать флажок «на всякий случай».

### STD-SEC-003. Привилегированный режим включают точечно и после проверки права

- Тип: `OFFICIAL_STANDARD`
- Сила: требование источника
- Проверка источника: 2026-10-15, статус `body_reviewed`
- Область платформы: управляемое приложение, обычное приложение
- Область: безопасность, права

[Использование привилегированного режима](https://its.1c.ru/db/v8std/content/485/hdoc) (#std485, пункты 1.2, 2.3, 3.1, 3.2, 3.3)

Привилегированный режим нужен, чтобы выполнить разрешенную пользователю операцию с недоступными ему служебными данными или ускорить работу, не расширяя доступ. Его включают на короткий участок. Экспортный метод не должен безусловно включать привилегированный режим. При недостатке прав вызывают ВыполнитьПроверкуПравДоступа. Данные, прочитанные в привилегированном режиме, не передают на клиент, если пользователю они недоступны.

Что делает агент:
- Не оборачивать весь экспортный метод в УстановитьПривилегированныйРежим(Истина).
- Проверять право до повышения привилегий.
- Не возвращать на клиент выборку, полученную только за счет привилегированного режима.

### STD-SEC-004. Право в коде проверяют через ПравоДоступа или РольДоступна по смыслу роли

- Тип: `OFFICIAL_STANDARD`
- Сила: рекомендация источника
- Проверка источника: 2026-10-15, статус `body_reviewed`
- Область платформы: управляемое приложение, обычное приложение
- Область: права

[Проверка прав доступа](https://its.1c.ru/db/v8std/content/737/hdoc) (#std737, пункты 1, 3, 4.1, 4.2)

При большом числе ролей видимость полей формы ролями не настраивают: либо делают отдельные формы, либо проверяют право в коде. Для проверки права на объект используют ПравоДоступа. РольДоступна — когда роль не дает прав на метаданные, а отмечает дополнительное право. Роль с правами «ГДЕ ЛОЖЬ» вместо проверки роли не проектируют.

Что делает агент:
- Проверять доступ к объекту через ПравоДоступа.
- Не плодить роль, у которой единственное право — ГДЕ ЛОЖЬ.

### STD-SEC-005. Выполнить и Вычислить на сервере не принимают произвольный код

- Тип: `OFFICIAL_STANDARD`
- Сила: требование источника
- Проверка источника: 2026-10-15, статус `body_reviewed`
- Область платформы: управляемое приложение, обычное приложение
- Область: безопасность

[Ограничения на использование Выполнить и Вычислить на сервере (Раздел обновлен!)](https://its.1c.ru/db/v8std/content/770/hdoc) (#std770, пункты 1, 2, 3, 4.1, 4.3, 4.5)

От Выполнить и Вычислить отказываются, кроме неизменного внешнего кода, который можно заранее проверить. Пользовательскую формулу собирают из разрешенных частей. Если Выполнить неизбежен, перед ним включают безопасный режим и не дают вызвать произвольные методы. Код, собранный из клиентских параметров или данных базы, считают опасным. Для вызова метода по имени переходят на прямой вызов. Регламентное задание по умолчанию работает с полными правами, безопасный режим сам по себе эти права не уменьшает.

Что делает агент:
- Не подставлять текст из реквизита, параметра формы или базы в Выполнить.
- Заменять вызов по имени строки прямым вызовом процедуры.
- Если динамическое выполнение остается, включать безопасный режим и ограничивать доступные методы.

На клиенте Выполнить и Вычислить тоже не используют для произвольного кода. Нельзя получить текст с сервера или из базы и выполнить его на клиенте. Вызов по имени заменяют прямым вызовом. Если выражение остается, непосредственно перед ним проверяют, что строка содержит только допустимое имя.

Что делает агент:
- Не выполнять на клиенте строку, пришедшую с сервера.

[Ограничение на выполнение внешнего кода (Раздел обновлен!)](https://its.1c.ru/db/v8std/content/669/hdoc) (#std669, пункты 1, 2, 3)

Код, который не является частью конфигурации, нельзя выполнять на сервере в небезопасном режиме, пока он не прошел аудит. Интерактивное открытие внешних обработок через «Файл — Открыть» по умолчанию отключают. Перед подключением внешнего кода администратора явно предупреждают. Обычным пользователям повторное предупреждение не показывают, если администратор уже подтвердил код.

Что делает агент:
- Не предлагать выполнение внешней обработки на сервере без безопасного режима и без сценария аудита.
- Не включать право интерактивного открытия внешних обработок всем пользователям.

### STD-SEC-008. Пароли не хранят в обычных реквизитах и не возят на клиент

- Тип: `OFFICIAL_STANDARD`
- Сила: требование источника
- Проверка источника: 2026-10-15, статус `body_reviewed`
- Область платформы: управляемое приложение, мобильное приложение, обычное приложение
- Область: безопасность, интеграции

[Безопасное хранение паролей](https://its.1c.ru/db/v8std/content/740/hdoc) (#std740, пункты 2, 3.1, 3.3)

Уточнение источника: Безопасное хранилище БСП статья рекомендует при использовании БСП. Само хранилище БСП не является обязательным для конфигурации без БСП.

Пароли и другую конфиденциальную информацию не хранят в информационной базе без отдельной защиты; предпочтительно спрашивать их у пользователя и сразу передавать. Если хранение необходимо, его выносят в отдельный объект с ограниченным доступом, а не в реквизит повседневного справочника. Пароль не держат в реквизите формы: иначе он уйдет на клиент.

Что делает агент:
- Не добавлять реквизит Пароль в справочник, с которым работает пользователь.
- Не помещать пароль в данные формы.
- Читать секрет на сервере непосредственно перед использованием.

### ENG-REV-007. Вопрос пользователю на управляемой форме задают асинхронно

- Тип: `ENGINEERING_RECOMMENDATION`
- Сила: не применяется, это не официальный стандарт
- К стандартам фирмы «1С» это правило не относится.
- Область: формы

Основание: Инженерная реализация STD-CS-005. Синтаксис ВопросАсинх относится к платформе, а не к отдельной процитированной статье v8std.

Официальный запрет модальности зафиксирован в STD-CS-005 (#std703). Конкретная пара ВопросАсинх и Ждать — способ платформы выполнить этот запрет. Вложенный Ждать через общий модуль, который сам задает вопрос, путает сценарий.

Что делает агент:
- На управляемой форме не вызывать синхронные Вопрос и Предупреждение.
- Задавать вопрос через ВопросАсинх в асинхронной процедуре и получать ответ через Ждать.
- Не объявлять саму цепочку Асинх/Ждать текстом стандарта #std703.
- Не вкладывать второй вопрос внутрь серверного или общего модуля, которого форма уже ждет.
