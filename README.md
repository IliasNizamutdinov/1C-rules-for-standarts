# Правила разработки 1С для Cursor и OpenCode

Набор правил помогает агенту писать и проверять код 1С так, чтобы было видно, какое требование взято из системы стандартов фирмы «1С», какое является инженерной рекомендацией, а какое относится только к конкретному проекту.

Репозиторий не заменяет ИТС и не дает гарантии, что весь код пройдет проверку конфигурации. Он делает проверку прослеживаемой: у официального правила есть номер статьи, ссылка, дата чтения и сила формулировки.

Дата последней сверки источников: **2026-10-15**.

## Источник

Основной источник — [Система стандартов и методик разработки конфигураций для платформы 1С:Предприятие 8](https://its.1c.ru/db/v8std).

Оглавление снято с дерева `https://its.1c.ru/db/metadata/v8std/nav_tree` и списков `nav_list`. Текст статьи читался из HTML, который страница документа открывает во фрейме `/db/content/v8std/src/...`. Ссылка в правилах ведет на постоянный адрес вида `https://its.1c.ru/db/v8std/content/<номер>/hdoc`, а не на главную страницу базы.

Повторная проверка: открыть те же URL, сравнить текст с формулировкой правила, обновить `checked_on`, пересобрать адаптеры и прогнать `python3 scripts/validate.py`. Порядок описан в [docs/rules-policy.md](docs/rules-policy.md).

## Три типа правил

| Тип | Где лежит | Как говорить в отчете |
| --- | --- | --- |
| `OFFICIAL_STANDARD` | `rules/official/` | Требование или официальная методическая рекомендация конкретной статьи |
| `ENGINEERING_RECOMMENDATION` | `rules/recommendations/` | Рекомендация этого репозитория, не стандарт фирмы «1С» |
| `PROJECT_REQUIREMENT` | `rules/project/` | Требование организации. Шаблон по умолчанию выключен |

Методическая рекомендация внутри официальной статьи не переносится в инженерные правила и не называется обязательным запретом. Сила записана в поле `normative_strength`.

## Что покрыто

Официальные правила собраны по прочитанным статьям о модулях, именах, запросах, проведении, транзакциях, блокировках, регистрах, общих модулях, клиент-серверных вызовах, правах, `Выполнить`/`Вычислить`, паролях, сообщениях пользователю, печати и локализуемых строках.

Каталог оглавления шире набора правил. Статус каждой статьи — в [docs/standards-catalog.md](docs/standards-catalog.md). Статьи, текст которых получен, но отдельное правило не выделено, перечислены в [docs/coverage.md](docs/coverage.md).

## Состав репозитория

| Путь | Назначение |
| --- | --- |
| `rules/official/` | Канон официальных правил |
| `rules/recommendations/` | Канон инженерных рекомендаций |
| `rules/project/template.json` | Выключенный образец проектных требований |
| `catalog/standards.json` | Снимок оглавления на 2026-10-15 |
| `catalog/adapter-manifest.json` | Какое правило в каком адаптере |
| `.cursor/rules/*.mdc` | Адаптер Cursor |
| `AGENTS.md`, `opencode.json`, `opencode/instructions/` | Адаптер OpenCode |
| `docs/` | Установка, политика, каталог |
| `examples/` | Сценарии запросов и отчетов |
| `scripts/render_adapters.py` | Пересборка адаптеров из JSON |
| `scripts/validate.py` | Проверка структуры и совпадения адаптеров |

Адаптеры не правят руками. После изменения JSON запускают:

```bash
python3 scripts/render_adapters.py
python3 scripts/validate.py
```

## Установка

- [Cursor](docs/INSTALL_CURSOR.md) — файлы `.cursor/rules/*.mdc` в корне проекта.
- [OpenCode](docs/INSTALL_OPENCODE.md) — `AGENTS.md`, `opencode.json` и семь файлов `opencode/instructions`, перечисленных в конфигурации.
- [Как пользоваться и как выглядит отчет](docs/USAGE.md).

Кратко для одного проекта, в котором своих правил еще нет.

Bash:

```bash
git clone https://github.com/IliasNizamutdinov/1C-rules-for-standarts.git /tmp/1c-rules
mkdir -p .cursor/rules opencode/instructions
cp /tmp/1c-rules/.cursor/rules/*.mdc .cursor/rules/
cp /tmp/1c-rules/AGENTS.md /tmp/1c-rules/opencode.json ./
cp /tmp/1c-rules/opencode/instructions/0*.md /tmp/1c-rules/opencode/instructions/1*.md \
   /tmp/1c-rules/opencode/instructions/2*.md /tmp/1c-rules/opencode/instructions/3*.md \
   /tmp/1c-rules/opencode/instructions/4*.md /tmp/1c-rules/opencode/instructions/5*.md \
   opencode/instructions/
```

Файл `90-project-template.md` копировать в OpenCode не нужно: он не входит в `instructions`. В Cursor он лежит среди правил, но подключается только вручную через `@`.

Для нескольких проектов удобнее подмодуль `vendor/1c-rules` и пути к его файлам. Плюсы и ограничения — в инструкциях установки. Удаленный URL в OpenCode зависит от сети и таймаута около пяти секунд.

Свои `AGENTS.md` и ключи `opencode.json` при обновлении не затирают. Обновляют семь файлов инструкций и восемь `.mdc`, кроме собственных файлов с другими именами.

## Проверка

Структура:

```bash
python3 scripts/validate.py
```

Скрипт проверяет идентификаторы, типы, ссылки официальных правил на каталог, дату, присутствие формулировки в адаптерах Cursor и OpenCode и то, что шаблон проекта не загружается сам. Он не доказывает полноту пересказа статьи и не заменяет чтение ИТС.

Проверка в агенте: новый чат, запрос из [examples/04-standards-check.md](examples/04-standards-check.md). В ответе должны быть `STD-MOD-011` и `STD-DATA-008`, а не общая фраза без источника.

## Ограничения

- 15 октября 2026 года оглавление содержало 321 документ. Текст получен не у всех. Правила выведены только из статей со статусом `body_reviewed`, и не из каждой прочитанной статьи.
- Заголовок «Методическая рекомендация» в статье часто относится только к части пунктов. Это отражено в силе правила, но автоматическая проверка не сверяет границу пунктов с живым сайтом.
- Стандарты интерфейса 8.2 и обычного приложения в основном остались на уровне названий.
- Рекомендации, которые в статье зависят от БСП, не включены как обязательные: библиотеки в конфигурации может не быть.
- Примеры кода в `examples/` используют условные имена объектов. Их нельзя переносить в конфигурацию без сверки метаданных.
- Репозиторий не запускает платформу 1С и не исполняет запросы.
- Тексты ИТС не копируются. В правилах — короткий пересказ и ссылка.
