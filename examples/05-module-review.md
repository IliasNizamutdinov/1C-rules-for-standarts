# Пример. Ревью существующего модуля

## Запрос

«Сделай ревью серверного общего модуля РасчетСкидок. Модуль вызывают с формы и из проведения.»

К ревью прикладывают сам модуль. Без текста модуля агент не должен выдумывать процедуры.

## Какие правила подключать

- `30-data-architecture` — контекст общего модуля и флажок вызова сервера.
- `40-client-server-security` — что можно вернуть на клиент.
- `20-queries` — если в модуле есть запросы.
- `10-modules` — имена, экспорт, комментарии программного интерфейса.
- `00-policy`.

## Что проверяет агент

- Один модуль не смешивает клиентский вызов и внутреннее проведение, если для этого нужны разные флажки (`STD-ARCH-001`, `STD-SEC-002`).
- Экспортный метод с вызовом сервера не включает привилегированный режим на весь текст (`STD-SEC-003`).
- Запросы в цикле ищутся и как прямые, и как вызовы функций (`STD-QRY-003` и отдельно `ENG-REV-005`).
- Экспортные функции программного интерфейса документированы (`STD-MOD-009`).

## Отчет

Отчет строится по процедурам, которые реально есть в файле. Шаблон одного замечания:

```text
Официальные требования
- STD-SEC-002. Процедура РассчитатьДляПроведения лежит в модуле с флажком «Вызов сервера»,
  хотя форма ее не вызывает.
  Место: общий модуль РасчетСкидок, процедура РассчитатьДляПроведения.
  Источник: https://its.1c.ru/db/v8std/content/679/hdoc
  Что сделать: перенести процедуру в серверный модуль без вызова с клиента.

Инженерные рекомендации
- ENG-REV-003. Рядом уже есть РассчитатьСкидкуСтроки. Новую функцию с тем же назначением не добавлять.
  Это рекомендация репозитория, не стандарт фирмы «1С».

Нужна проверка по источнику
- Не подтверждалось, есть ли в конфигурации БСП и модуль ОбщегоНазначения.
```

Если процедура из примера в модуле не найдена, замечание `STD-SEC-002` не ставят.
