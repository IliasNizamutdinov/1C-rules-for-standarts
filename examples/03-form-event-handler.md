# Пример. Обработчик события формы

## Запрос

«В форме документа при изменении контрагента подставь договор по умолчанию.»

## Какие правила подключать

- `40-client-server-security`: где выполнять поиск договора и сколько раз ходить на сервер.
- `50-forms-applied`: как сообщить, что договор не найден.
- `10-modules`: имя обработчика и отсутствие лишнего комментария «это обработчик ПриИзменении».
- `00-policy`.

## Что проверяет агент

- Поиск договора не написан циклом на клиенте и не вызывает сервер на каждую строку.
- Серверный метод без нужды не тащит весь контекст формы (`STD-CS-004`).
- На клиенте нет синхронного `Вопрос` (`STD-CS-005`). Конкретный `ВопросАсинх` — это `ENG-REV-007`, если вопрос пользователю вообще нужен.
- Сообщение идет через `СообщениеПользователю` и `НСтр`, если пользователь видит текст.
- Договор не читают через точку от ссылки с загрузкой всего объекта, если нужны отдельные реквизиты (`STD-DATA-005`).

## Отчет

```text
Официальные требования
STD-CS-001: чтение договора выполняется одним серверным вызовом, данные для открытия формы заранее не требуются.
STD-UI-001: при пустом результате пользователь получает СообщениеПользователю, а не Сообщить.
STD-UI-004: текст сообщения в НСтр.

Официальные методические рекомендации
Нет.

Инженерные рекомендации
ENG-REV-007 не применяется: вопрос пользователю в сценарии не нужен.
Не называйте отсутствие ВопросАсинх нарушением стандарта.

Требования проекта
Не заданы.

Нужна проверка по источнику
Правило выбора договора по умолчанию в стандартах v8std не найдено. Его должен задать проект.
```

Пример не задает универсальный алгоритм «договор по умолчанию»: такого правила в прочитанных стандартах нет.
